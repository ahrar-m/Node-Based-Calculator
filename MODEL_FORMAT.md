# Model Format (JSON) — v0.1

A model is a single JSON file. It can be written by hand, exported from the app, or **generated by any AI** using [AI_PROMPT.md](AI_PROMPT.md). Worked examples: [business expenses](../examples/business-expenses.model.json), [beam design](../examples/beam-design.model.json).

## Top-level shape

```jsonc
{
  "formatVersion": "0.1",
  "id": "unique-id",
  "name": "My Business Finances",
  "description": "Annual expense rollup across departments.",
  "root": "total_expenses",        // name of the single most important term
  "libraries": [ ... ],            // project-scoped constant libraries (optional)
  "globalLibraries": ["common"],   // names of global libraries to pull constants from (optional)
  "terms": [ ... ]                 // all terms
}
```

## Constant library entry

```jsonc
{
  "id": "c-tax",
  "name": "tax_rate",
  "value": 0.08,
  "unit": "fraction",
  "description": "Effective tax rate.",
  "slider": { "min": 0, "max": 0.25, "step": 0.01 },
  "snapshots": [
    { "label": "Low (5%)", "value": 0.05 },
    { "label": "Current (8%)", "value": 0.08 },
    { "label": "High (12%)", "value": 0.12 }
  ]
}
```

- **slider** makes the constant adjustable in the UI with safe limits.
- **snapshots** are saved values — click one in the UI to apply it instantly.

## Term kinds

| kind | meaning | formula |
|---|---|---|
| `value` | plain number (or period-tagged input) | optional |
| `formula` | computed from other names | required |
| `group` | container for children | optional (defaults to **sum of children**) |

```jsonc
{
  "id": "g-ops",
  "kind": "group",
  "name": "operations",
  "period": "year",
  "unit": "USD",
  "description": "Everything needed to run the core work.",
  "children": ["salaries", "rent", "utilities"]   // term names or inline term objects
}
```

Every term may carry: `id` (unique), `kind`, `name` (unique identifier: letters/digits/underscore only), `description` (plain language — shown when the user clicks the block), `formula`, `period`, `unit`, `slider`, `snapshots`.

## Periods / time buckets

`once`, `week`, `month`, `year`. When a child feeds a parent, its value converts to the **parent's period**:

| child → parent | factor |
|---|---|
| week → year | ×52 |
| month → year | ×12 |
| once → anything | ×1 |
| same period | ×1 |

Built-in helpers usable inside formulas: `weekly(x)`, `monthly(x)`, `yearly(x)`.

## Formula syntax (v0.1)

- References are term names or library constant names: `rent + salaries * 1.1`.
- Operators: `+ - * / ^` and parentheses.
- Functions: `sum(...)`, `min(...)`, `max(...)`, `avg(...)`, `round(x, digits)`, `if(cond, a, b)`, comparisons `> < >= <= == !=`.

## Resolution & validation

- Lookup order: term names → project library constants → global library constants.
- **No undefined references** — import fails with a clear message.
- **No cycles** — a circular chain is rejected with the names involved.

## Verification sample (used in dev tests)

From the expenses example: total = ((salaries×12) + (rent×12) + (utilities×12) + (marketing×52) + equipment) × (1 + tax_rate) = ((54000 + 24000 + 3600) + 41600 + 25000) × 1.08 = **160,056/year**.
